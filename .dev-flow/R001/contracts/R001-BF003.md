## Implementation Scope

### 目标
新增 Kotlin pure JVM auth model，作为后续 `ControlPlane`、`HttpSseTransport` 和 Flutter bridge 接入鉴权的共享基础。实现必须提供 `DebugAuthManager`、`DebugAuthDecision`、`DebugAuthRequest`、`DebugAuthTokenRecord`、默认 no-op manager、Bearer header helper、route classification，以及 hash/expiry/revoked 判定能力，同时保持当前未启用鉴权时的裸用行为。

### 范围内
- 新建 `kotlin/src/main/kotlin/com/pantas/debug/controlplane/DebugAuth.kt`。
- 新建 `kotlin/src/test/kotlin/com/pantas/debug/controlplane/DebugAuthTest.kt`。
- 定义 pure JVM `DebugAuthManager`，至少包含任务给定接口意图：`authorize(request: DebugAuthRequest): DebugAuthDecision` 和 `helloAuthState(token: String?): Map<String, Any?>` 或等价 API。
- 定义 `DebugAuthDecision` sealed result：`Authorized`、`Denied(statusCode, code, message)`。
- 定义 `DebugAuthRequest`，能表达 HTTP method、path segments、route classification、Bearer token、请求 body/opaque request handle 中本任务需要的最小鉴权上下文。
- 定义 `DebugAuthTokenRecord`，支持 `tokenId`、`tokenHash`、`createdAt`、`expiresAt`、`revokedAt?`、`clientLabel?` 或等价字段；不得保存明文 token。
- 定义 route classification：`HELLO_BOOTSTRAP`、`AUTH_BOOTSTRAP`、`SENSITIVE`。
- 提供 route classification helper：`GET /hello` 为 `HELLO_BOOTSTRAP`；`POST /auth/request`、`POST /auth/status`、`POST /auth/claim` 为 `AUTH_BOOTSTRAP`；`/state`、`/events` 和 capability routes 为 `SENSITIVE`。
- 提供 Bearer header helper，能从 header map 或 header value 中解析 `Authorization: Bearer <opaque-token>`，并拒绝缺失、非 Bearer、空 token、额外无效格式。
- 提供 token hash helper 或 token record 校验 helper，使用 JVM 标准库实现 SHA-256 或等价稳定 hash，支持 hash match、expired、revoked 三类判定。
- 提供默认 no-op auth manager，保持未配置 auth manager 时 `Authorized`，并让 `/hello` auth state 表达未启用或无需鉴权的状态。
- 单元测试覆盖 authorized、authorization required、invalid token、expired、revoked、route classification、Bearer parsing、no-op manager 行为。

- 不实现 Flutter UI、Flutter MethodChannel、Dart API 或 Android bridge。

- 不实现 OAuth、JWT、refresh token、RBAC/scope、多用户权限体系或完整 MCP server。
- 不持久化 Android `SharedPreferences`、Keystore、文件系统 token store 或任何业务侧存储。

### 已知约束
- 本任务是 foundation 层，依赖 R001-BF001/R001-BF002 的协议与 fixtures；可引用错误 code 和 auth route 名称，但不改变协议真相源。
- Kotlin module 是纯 JVM core；新增文件不得 import Android、Flutter、业务包或 Python 相关依赖。
- 架构要求真实资源边界在 App debug plane，token 不得通过 query string 传递，HTTP 请求使用 `Authorization: Bearer <token>`。
- `RouteRequest` 当前没有 first-class headers 字段；本任务只能提供 Bearer helper，实际从 NanoHTTPD `IHTTPSession.headers` 注入或封装到请求上下文属于后续 BF004 接入范围。
- 默认 no-op manager 是兼容性边界：宿主未显式启用 auth 时，现有 `/hello`、`/state`、`/events` 和 capability dispatch 行为不应因本任务变化。
- hash/expiry/revoked 支持必须可单元测试，不依赖真实时钟不可控行为；测试应使用 deterministic clock 或显式 `Instant` 参数。

### 任务流程图
1. route classification:
   - 输入 method + path segments。
   - `GET /hello` -> `HELLO_BOOTSTRAP`。
   - `POST /auth/request|status|claim` -> `AUTH_BOOTSTRAP`。
   - 其他 system sensitive routes `/state`、`/events` 与 capability route candidates -> `SENSITIVE`。
   - 未知路径默认仍按 `SENSITIVE` 分类，避免新增敏感 capability route 被误判公开。

2. Bearer header parsing:
   - 输入 authorization header value 或 headers map。
   - 缺失 header -> token 为 null 或 denied helper result。
   - `Bearer test-token` -> 返回 `test-token`。
   - 空 token、非 Bearer scheme、格式不合规 -> 返回 null 或可区分 invalid result；不得接受 query/body/cookie token。

3. default no-op manager:
   - 后续接入方未配置真实 manager 时调用 no-op manager。
   - no-op manager 对任意 `DebugAuthRequest` 返回 `Authorized`。
   - `helloAuthState(token)` 返回不要求授权或未启用的稳定字段，不泄露 token。

4. token record validation:
   - 输入 plain token、`DebugAuthTokenRecord`、当前时间。
   - plain token hash 与 `tokenHash` 匹配且未过期且未撤销 -> `Authorized`。
   - 缺 token -> `Denied(401, "authorization_required", ...)`。
   - hash 不匹配或格式错误 -> `Denied(401, "invalid_token", ...)`。
   - 当前时间超过 `expiresAt` -> `Denied(401, "token_expired", ...)`。
   - `revokedAt != null` -> `Denied(401, "token_revoked", ...)`。

5. 后续跨模块交互点:
   - BF004 可在 `ControlPlane` 和 `HttpSseTransport` 接入本任务提供的 manager、classification 和 Bearer helper。
   - FF001 可在 Flutter bridge 层复用 auth request/token metadata model，但本任务不暴露 channel。
   - BF004/BB001 可沿用本任务稳定 error code，不在本任务实现 Python 行为。
