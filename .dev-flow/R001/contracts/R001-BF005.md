## Implementation Scope

### 目标
在 Kotlin `HttpSseTransport` 的生产 HTTP `/events` 劫持路径接入 debug auth preflight：启用 auth 时，`GET /events` 必须在 `hijackEvents()`、响应头写入、首帧 `: connected\n\n` 写入和 subscriber 注册之前完成 Bearer token 校验；鉴权失败返回既有 JSON 401/403 错误体；鉴权成功后保持现有 SSE 字节契约、headers、flush 和广播行为不变。

### 范围内
- 修改 `HttpSseTransport`，让 `/events` hijack 前可调用 auth checker、preflight handler 或等价 transport-level gate。
- 复用 BF004 已引入的 `DebugAuthManager`、`DebugAuth.bearerToken(headers)`、`DebugAuthDecision.Denied` 和 `{ok:false, code, message}` 错误映射；不新增第二套 auth result taxonomy。
- 在 `GET /events` 且 path segments 恰好为 `["events"]` 时，先构造 `DebugAuthRequest(method="GET", segments=["events"], routeClass=SENSITIVE, bearerToken=..., request=session)` 或等价请求上下文。
- auth disabled 时保持当前裸用行为：`GET /events` 仍立即返回 SSE 200、`text/event-stream`、首帧 `: connected\n\n`，并注册 subscriber。
- auth enabled 且 authorized 时保持当前 SSE 行为：状态码 200、`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`Connection: keep-alive`、首帧字节级 `: connected\n\n`、subscriber count 增加、broadcast 帧格式不变。
- auth denied 时短路为 JSON HTTP response：401/403 status、`application/json` body、code/message 与 `PROTOCOL.md` §2.4 一致；不得调用 `hijackEvents()`，不得写任何 SSE 字节，不得增加 subscriber count。
- 做必要 wiring，使 `ControlPlaneServer.create(...)` 或等价装配点能把同一个 `DebugAuthManager` 传给 `ControlPlane` 和 `HttpSseTransport`；若实现选择由 `ControlPlane` 提供 preflight function，也必须保证 transport 层能在 dispatch 前调用。
- 新增或扩展 focused Kotlin transport test，覆盖 unauthorized/denied pre-hijack、authorized first frame、disabled compatibility 和 subscriber count。

### 范围外
- 不实现 OAuth、JWT、RBAC、scope、多用户权限、refresh token 或完整 MCP HTTP server。
- 不修改 Flutter、Dart、Python、fixtures 或 `PROTOCOL.md`。
- 不实现 Android UI、pending signal bridge、SharedPreferences、Keystore、token persistence 或授权弹窗。
- 不主动断开已经建立但中途过期/撤销的 SSE 连接；第一版只做建连鉴权。
- 不改变 `/hello`、`/state`、capability routes、`/auth/request`、`/auth/status`、`/auth/claim` 的 BF004 语义，除非是为了把现有 auth manager wiring 传递到 transport。
- 不接受 query string、URL path、request body、cookie、SSE event data、`appMeta` 或 `/hello` 聚合 state 中的 token。

### 已知约束
- `PROTOCOL.md` §1.4 明确 `/events` 在 `HttpSseTransport` 中 dispatch 前劫持；只在 `ControlPlane.dispatch` 加 gate 会漏掉生产 SSE。
- `PROTOCOL.md` §2.2 要求敏感请求只能通过 `Authorization: Bearer <opaque-token>` header 传 token，`/events` 属于敏感端点。
- `PROTOCOL.md` §1.4/§4.4/§4.7 要求 authorized SSE 首帧字节级 `: connected\n\n`，且建连后 subscriber 才参与广播。
- `.dev-flow/architecture.md` 要求真实资源边界在 App debug plane，Python 只携带凭证和翻译错误。
- Kotlin core 必须保持纯 JVM，不依赖 Android UI/storage。

### 任务流程图
1. request enters transport:
   - `HttpSseTransport.serve(session)` 解析 `method`、`segments`、`headers`。
   - 非 `GET /events` 路径保持现有 parse body + dispatch flow。

2. auth disabled:
   - transport 没有 auth checker / auth manager 为 null。
   - `GET /events` 直接执行当前 `hijackEvents()`。
   - 首帧、headers、subscriber lifecycle 与既有 tests 完全一致。

3. `/events` preflight:
   - 命中 `method == GET && segments == listOf("events")`。
   - 从 `session.headers` 解析 Authorization Bearer token。
   - 调用同一 auth manager/checker 生成 `DebugAuthDecision`。

4. denied branch:
   - `Denied(statusCode, code, message)` -> `RouteResult.error(statusCode, code, message).toNanoResponse()`。
   - 返回 `application/json`，body 为 `{ok:false, code, message}`。
   - 不调用 `hijackEvents()`，不创建 `SseSubscriber`，不写 `: connected`，`subscriberCount()` 保持不变。

5. authorized branch:
   - `Authorized` -> 调用 `hijackEvents()`。
   - response/status/headers/首帧和 broadcast frame 格式保持 BF002/BF003 既有契约。
   - `subscriberCount()` 按当前逻辑增加，断连/close 清理逻辑保持。

6. wiring:
   - `ControlPlaneServer.create(scope, appMeta, port, authManager)` 或等价装配方式把同一个 auth provider 用于 `ControlPlane` 普通路由 gate 和 `HttpSseTransport` SSE pre-hijack gate。
   - 既有无 auth 调用点继续编译并保持裸用行为。
