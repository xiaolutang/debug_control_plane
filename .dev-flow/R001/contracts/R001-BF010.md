# Sprint Contract: R001-BF010

## Implementation Scope

Close R001 auth work with a CI-level regression gate that proves the Kotlin,
Dart, Flutter plugin, Flutter Android plugin JVM, Python, zero-business-dep,
protocol-version, and aggregate CI entry points are wired and pass. If a host
cannot execute a command, the implementer must record an explicit environment
blocker with enough detail for evaluator review; that blocker is evidence for
`blocked`, not a substitute PASS.

In scope:
- Audit the existing CI/test entry points in `ci/ci-check-all.sh`,
  `ci/zero-business-dep-check.sh`, and `ci/protocol-version-guard.sh`.
- Ensure `ci/ci-check-all.sh` is the final all-up local/CI gate for R001 auth.
- Confirm auth tests added by R001-BF006, R001-BF008, R001-FF003, and R001-BB001
  are reachable through the all-up gate.
- If the Flutter Android plugin JVM tests are not covered, add only the missing
  CI invocation path for `flutter_debug_control_plane/android` Gradle
  `testDebugUnitTest` and keep the test semantics unchanged.
- Record final verification evidence for every required command, including
  explicit environment blockers when a command cannot run in the current host.

Out of scope:
- No auth protocol, route, token, storage, bridge, MCP, Kotlin, Dart, Flutter,
  or Python business implementation changes.
- No changes to `PROTOCOL.md`, fixtures, auth error codes, `protocolVersion`,
  or API payload semantics.
- No new auth test behavior unless the only blocker is that an existing required
  test entry is not invoked by CI.
- No business package imports, no dependency additions, and no CI shortcut that
  skips a required regression surface.

Known constraints:
- Architecture requires zero business dependencies, protocol truth from
  `PROTOCOL.md` and `fixtures/`, cross-language field/error/protocol-version
  consistency, root Gradle as Kotlin-only aggregator, and Flutter plugin Android
  as its own standalone Gradle project.
- Current `ci/ci-check-all.sh` runs root `./gradlew build`, Dart tests, Flutter
  plugin Dart tests, Python pytest, `zero-business-dep-check.sh`,
  `protocol-version-guard.sh`, and publish checks.
- Root `settings.gradle.kts` includes only `:kotlin`; it does not include
  `flutter_debug_control_plane/android`.
- `tool/release.sh` already documents the standalone Flutter Android plugin JVM
  command:
  `cd flutter_debug_control_plane/android && ../../kotlin/gradlew -p . testDebugUnitTest`.

## Required API/CLI Shape

The final verification surface must include these commands exactly or with a
documented equivalent path that runs the same tests:

1. `./gradlew build`
2. `cd dart && fvm flutter test`
3. `cd flutter_debug_control_plane && fvm flutter test`
4. `cd flutter_debug_control_plane/android && ../../kotlin/gradlew -p . testDebugUnitTest`
5. `cd python && ${PYTHON_BIN:-python3} -m pytest tests -q --no-header`
6. `bash ci/zero-business-dep-check.sh`
7. `bash ci/protocol-version-guard.sh`
8. `bash ci/ci-check-all.sh`

`ci/ci-check-all.sh` requirements:
- It must run the Flutter Android plugin JVM test surface explicitly if root
  `./gradlew build` does not cover it.
- The step must fail fast with the underlying command exit code.
- It must preserve existing `PYTHON_BIN` behavior and existing step ordering
  unless changing the order is required to run a prerequisite.
- It must not hide failures with `|| true`, broad skip flags, or log-only
  warnings for required gates.

## Flow Requirements

Normal full gate:
1. Run root Kotlin build/test through `./gradlew build`.
2. Run Dart package tests with `fvm flutter test`.
3. Run Flutter plugin Dart tests with `fvm flutter test`.
4. Run Flutter Android plugin JVM tests through the standalone Android Gradle
   project using `testDebugUnitTest`.
5. Run Python pytest.
6. Run zero-business-dep and protocol-version guards.
7. Run `ci/ci-check-all.sh` and confirm it exercises the same required surfaces.
8. Write evidence logs with command, status, exit code, passed count when
   available, and any environment blocker.

Environment blocker flow:
- If JDK, Android Gradle tooling, Flutter/fvm, Python interpreter, pytest deps,
  or network-resolved Gradle artifacts are unavailable, record the exact command,
  exit code, missing tool/error summary, and why it is an environment blocker.
- A blocker can explain an unexecuted command, but it cannot be used to omit CI
  wiring that is inspectable in source.
- ENV_BLOCKED is not PASS. Any ENV_BLOCKED required command must make the
  evaluator return `blocked` or `fail` with `commit_ready=false` unless the same
  required command also has independent passing evidence from an equivalent
  environment.
