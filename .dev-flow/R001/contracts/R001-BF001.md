### 范围内

- 新增 Auth 相关协议章节，放在系统路由、SSE 或错误契约附近，并保持文档结构可读。
- 明确定义 `Authorization: Bearer <opaque-token>` 只能通过 HTTP header 传递，禁止 query string token。
- 明确定义未授权 `GET /hello` 的最小 bootstrap 响应、授权后完整 hello 响应，以及二者字段差异。

- 明确 `GET /events` 必须在 SSE hijack 前鉴权；失败时返回 JSON 401/403，不能写入 `: connected` 首帧。
- 更新文档末尾速查表或等价摘要，使 auth 相关契约可快速定位。

### 已知约束
- `PROTOCOL.md` 与 `fixtures/` 是协议真相源；本任务只更新文档真相源，fixture 可执行投影由后续 R001-BF002 覆盖。
- 架构要求 token 不得通过 query string 传递，HTTP 请求必须使用 `Authorization: Bearer <token>`。
- 真实资源边界在 App debug plane；Python adapter 只能携带凭证和翻译错误，不能成为最终授权判定方。
- 未授权发现必须保留最小 bootstrap 能力，但不得泄露完整 `registeredCapabilities` 或聚合 state。
- `/events` 是传输层劫持路径，不经过普通 `ControlPlane.dispatch`；auth 失败必须发生在写 SSE header/首帧之前。
- `protocolVersion = 1` 是跨语言硬常量；本任务不得要求递增。

### 任务流程图
1. hello bootstrap:
   - Python/Agent `GET /hello` 不带 Bearer 或 Bearer 无效 -> App debug plane 返回 `200` 最小 bootstrap。
   - 最小 bootstrap 必须包含协议/服务发现所需字段和 auth 引导字段，如 `authRequired: true`、`authStatus`、`authEndpoints`。
   - 最小 bootstrap 不得返回 `registeredCapabilities`，也不得 spread capability 聚合 state。
   - Python/Agent `GET /hello` 携带有效 `Authorization: Bearer <token>` -> App debug plane 返回授权后完整 hello：保留既有完整字段、`registeredCapabilities`、聚合 state，并标注 authorized/auth status。

2. auth request/status/claim:
   - Python/Agent `POST /auth/request` body `{clientNonce, clientLabel?, requestedMethod?, requestedPath?}` -> App 创建或复用 pending authorization -> 返回 `202` 或等价明确状态，body 包含 `requestId`、`pairingCode`、`status`、`expiresAt`。
   - Python/Agent `POST /auth/status` body `{requestId, clientNonce}` -> App 返回 `pending`、`approved`、`denied` 或 `expired`，且 status 响应不返回明文 token。
   - 用户批准后，Python/Agent `POST /auth/claim` body `{requestId, clientNonce}` -> 首次 claim 成功返回 `{token, tokenId, expiresAt}`；重复 claim、过期、denied 或 nonce 不匹配必须返回明确错误。

3. Bearer header:
   - 已领取 token 的客户端访问 `/state`、`/events` 或 capability resource/command -> 请求头包含 `Authorization: Bearer <opaque-token>`。
   - App debug plane 对每次敏感请求校验 token hash、过期和撤销状态。
   - 文档必须声明 query string、body、cookie 或 appMeta 中传 token 均不是本协议的 token 传递方式。

4. 401/403:
   - 缺失 token 或未完成授权 -> `401 authorization_required`。
   - token 格式错误或 hash 不匹配 -> `401 invalid_token`。
   - token 过期 -> `401 token_expired`。
   - token 被撤销 -> `401 token_revoked`。
   - 用户拒绝 pending authorization -> `403 authorization_denied`。
   - future policy/scope 不足 -> `403 forbidden`。
   - 所有 auth 错误体沿用 `{ok:false, code, message}`，不新增强制 `auth` 嵌套字段。

5. SSE pre-hijack:
   - Python/Agent `GET /events` 不带有效 Bearer -> transport 在 hijack/writeHead/write首帧前短路。
   - 失败响应为 JSON 401/403，Content-Type 为 `application/json`。
   - 失败路径不得写入 `: connected\n\n`，不得注册 SSE subscriber。
   - 成功路径保持既有 SSE 契约：`200 text/event-stream`，首帧 `: connected\n\n`，后续事件帧格式不变。
