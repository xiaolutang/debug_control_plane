## Implementation Scope

### 目标
在 Kotlin `ControlPlane` 接入 App-side debug auth：宿主可选配置 `DebugAuthManager`，未配置时保持当前裸用行为；启用 auth 时，`GET /hello` 支持未授权最小 bootstrap 与授权完整 hello，`/state`、`/events` dispatch 兜底和 capability routes 在 handler 前短路鉴权；新增 `/auth/request`、`/auth/status`、`/auth/claim` bootstrap system routes，并扩展 `DebugAuth.kt` 以提供这些 routes 所需的 request/status/claim API 与 result types。

### 范围内
- 修改 `ControlPlane` 构造函数，接收可选 `authManager: DebugAuthManager? = null` 或等价参数；`null` 表示 auth 未启用，必须保持现有 `/hello`、`/state`、`/events` dispatch 兜底和 capability dispatch 行为。
- 修改 `RouteRequest`，新增 `headers: Map<String, String> = emptyMap()`，保持所有既有调用点源码兼容；本任务选择 first-class headers 字段，而不是从 `request: Any?` opaque handle 反射/类型分支提取 header。
- 修改 `HttpSseTransport` 的普通 dispatch 路径，把 NanoHTTPD session headers 转发到 `RouteRequest.headers`；这只覆盖非 hijack dispatch 请求，不实现 `/events` SSE pre-hijack 鉴权。
- 在 `ControlPlane.dispatch` 中，在 capability handler 或 sensitive system handler 执行前，对 `DebugAuthRouteClass.SENSITIVE` route 调用 `authManager.authorize(...)`；`Denied` 必须直接返回 `RouteResult.error(statusCode, code, message)`，不得调用 capability handler 或聚合 state。
- `GET /hello` 在 auth 未启用时返回当前完整 hello；auth 启用且无有效 token/无效 token/过期/撤销时返回 200 最小 bootstrap；auth 启用且授权通过时返回当前完整 hello 并包含 auth 状态字段。
- 新增 `POST /auth/request`、`POST /auth/status`、`POST /auth/claim` system routes，优先级高于 capability routes，按 `PROTOCOL.md` §2.3 映射成功状态码和响应 body，错误沿用 `{ok:false, code, message}`。
- 扩展 `DebugAuthManager`，增加 auth request/status/claim 所需方法和 result types；方法命名可按 Kotlin 风格调整，但必须能表达 request creation、request status polling、approved claim 一次性 token 领取、denied/expired/invalid outcomes。
- 新增 `ControlPlaneAuthTest.kt` 或等价 Kotlin test，覆盖 hello bootstrap、sensitive route gate、auth bootstrap routes、handler 不执行、未配置兼容行为、headers 传递和 RouteRequest 默认兼容。

### 范围外
- 不做 `HttpSseTransport` `/events` pre-hijack auth；生产 SSE 建连前鉴权属于 R001-BF005。
- 不修改 Flutter、Python、Dart。
- 不做 Android UI、pending signal bridge、persistence、SharedPreferences、Keystore。
- 不实现 OAuth、JWT、RBAC、refresh token、完整 MCP server。
- 不改变 `PROTOCOL.md`、fixtures、协议版本或既有 `/state` 无 `ok` 包裹契约。
- 不把 token 放入 query string、path、body、cookie、SSE event data、`appMeta` 或 `/hello` 聚合 state。

### 已知约束
- `.dev-flow/architecture.md` 要求真实资源边界在 App debug plane，Python 只携带凭证；本任务的最终授权判定必须发生在 Kotlin `ControlPlane`。
- `PROTOCOL.md` 是字节级协议真相源：未授权 `/hello` 不能包含 `registeredCapabilities` 或 capability 聚合 state；授权 `/hello` 必须保留完整 hello 语义；auth 错误体必须是 `{ok:false, code, message}`。
- `/auth/*` 是 system bootstrap routes，必须在 capability 分发前匹配；业务 capability 即使声明同路径也不得截获。
- `RouteRequest` 目前没有 headers。contract 选择添加 `headers: Map<String, String> = emptyMap()`，因为 dispatch 鉴权需要协议无关且可测试的 Bearer 输入；默认值保持旧构造调用兼容，也避免 `ControlPlane` 依赖 NanoHTTPD/transport-specific opaque request 类型。
- `ControlPlane.handleEvents` 只是非劫持传输兜底；本任务可通过 dispatch gate 保护它，但 HTTP/SSE transport 的 pre-hijack gate 明确留给 BF005。
- `DebugAuth.kt` 已有 BF003 基础类型；扩展时必须保持 BF003 测试语义兼容，不删除 no-op manager、Bearer helper、hash/expiry/revoked helper。

### 任务流程图
1. dispatch classification:
   - 输入 `RouteRequest(method, segments, headers, body, request)`。
   - `GET /hello` -> hello bootstrap handler。
   - `POST /auth/request|status|claim` -> auth bootstrap system handler。
   - `GET /state`、`GET /events` dispatch 兜底、capability GET/POST candidates、未知非 bootstrap route -> sensitive path。

2. auth disabled compatibility:
   - `authManager == null` 或等价 disabled 判定。
   - `/hello` 走现有完整 merge order。
   - `/state`、`/events` 兜底、capability routes 不做 auth short-circuit。
   - 既有 `ControlPlaneTest` 不因构造函数或 `RouteRequest` 新字段破坏。

3. hello auth path:
   - 从 `req.headers` 解析 Bearer token。
   - 有 auth manager 时调用 hello/auth 状态或 authorize 等价 API。
   - unauthorized/invalid/expired/revoked -> `RouteResult.Ok(status=200)` 最小 bootstrap：protocol/app discovery/server info、`eventsEndpoint`、`profileRevision`、`authRequired:true`、`authStatus`、`authEndpoints`；不得聚合 capability state，不得包含 `registeredCapabilities`。
   - authorized -> 当前完整 hello payload + `authRequired:true` + `authStatus:"authorized"` 或等价 auth state；不得泄露明文 token。

4. sensitive short-circuit:
   - 对 sensitive route 构造 `DebugAuthRequest`，包含 method、segments、routeClass、bearerToken、body、headers/opaque request 中必要上下文。
   - `Authorized` -> 继续执行原 system/capability handler。
   - `Denied(statusCode, code, message)` -> 立即返回 `RouteResult.error(...)`；测试需证明 handler 未执行、state 未聚合。

5. auth bootstrap routes:
   - `POST /auth/request` 读取 JSON object body，调用 auth manager request API；成功返回 202 `{ok:true, requestId, status:"pending", pairingCode?, expiresAt}`。
   - `POST /auth/status` 调用 status API；pending/approved/denied/expired 按协议返回，denied 映射 `403 authorization_denied`。
   - `POST /auth/claim` 调用 claim API；approved 且未 claim 时返回 200 `{ok:true, token, tokenId, expiresAt}`；unknown/nonce mismatch/already claimed 映射 `401 invalid_token`；expired 映射 `401 token_expired`；denied 映射 `403 authorization_denied`。

6. 后续跨模块交互点:
   - BF005 在 `HttpSseTransport` hijack 前复用 `RouteRequest.headers` 或相同 Bearer helper 完成 `/events` 真实 HTTP 长连接 gate。
   - Flutter/Python/Dart 后续任务复用协议字段和 error codes；本任务不修改这些模块。
