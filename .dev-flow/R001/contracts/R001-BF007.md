# Sprint Contract: R001-BF007

## Implementation Scope

Implement the Dart package mirror of Kotlin debug auth behavior for the debug control plane core.

In scope:
- Add a pure Dart auth abstraction equivalent to Kotlin `DebugAuth.kt`.
- Update Dart `ControlPlane` so auth-enabled requests match Kotlin route gating behavior.
- Update `/hello`: unauthenticated auth-enabled requests return minimal bootstrap; authorized requests return existing full response plus auth state.
- Add `/auth/request`, `/auth/status`, and `/auth/claim` system routes before capability dispatch.
- Update `HttpSseTransport` so `GET /events` runs auth preflight before response headers, subscriber registration, or writing `: connected\n\n`.
- Preserve current Dart behavior when auth is not enabled.
- Preserve `protocolVersion = 1`.

Out of scope:
- No OAuth, JWT, RBAC, scopes, refresh tokens, full MCP Streamable HTTP server, TLS, or transport encryption.
- No token query string, URL path, request body, cookie, SSE event data, `appMeta`, or `/hello` state propagation.
- No Dart token persistence, token generation, hash store, pairing UI, Flutter host UI, Android storage, Python client changes, or MCP adapter changes.
- No active disconnection of already-established SSE connections when a token later expires.
- No changes to business capability contracts.

## Required API Shape

Add Dart auth concepts mirroring Kotlin:
- `enum AuthRouteClass { helloBootstrap, authBootstrap, sensitive }`
- `class AuthRequest` with `method`, `segments`, `routeClass`, `bearerToken`, `body`, `request`.
- `sealed class AuthDecision`, `AuthAuthorized`, `AuthDenied(statusCode, code, message)`.
- `sealed class AuthRouteResult`, `AuthRouteOk(body, statusCode)`, `AuthRouteDenied(statusCode, code, message)`.
- `abstract interface class DebugAuthManager` with `authorize`, `helloAuthState`, `requestAuthorization`, `authorizationStatus`, `claimAuthorization`.

Helper semantics:
- `DebugAuth.classifyRoute(method, segments)`:
  - `GET /hello` -> `helloBootstrap`
  - `POST /auth/request|status|claim` -> `authBootstrap`
  - everything else -> `sensitive`
- `DebugAuth.bearerToken(headers)`:
  - Reads `Authorization` case-insensitively.
  - Accepts only `Bearer <opaque-token>`.
  - Rejects missing, blank, malformed, or whitespace-containing token values.
- Stable denial helpers:
  - `authorization_required`: HTTP 401, `Debug authorization is required.`
  - `invalid_token`: HTTP 401, `Debug authorization token is invalid.`
  - `token_expired`: HTTP 401, `Debug authorization token expired.`
  - `token_revoked`: HTTP 401, `Debug authorization token was revoked.`

## RouteRequest Headers

`RouteRequest` must carry headers:

```dart
class RouteRequest {
  const RouteRequest({
    required this.method,
    required this.segments,
    required this.body,
    required this.request,
    this.headers = const <String, String>{},
  });

  final Map<String, String> headers;
}
```

Requirements:
- Existing tests and non-HTTP transports remain source-compatible via default empty headers.
- `HttpSseTransport` populates headers for normal dispatched requests from `HttpRequest.headers`.
- Header names support case-insensitive Authorization parsing.
- `RouteContext.request` behavior remains unchanged.

## ControlPlane Requirements

Constructor:

```dart
ControlPlane({
  required this.transport,
  this.appMeta,
  this.authManager,
});
```

Auth disabled (`authManager == null`):
- Preserve existing `/hello`, `/state`, direct `/events`, and capability route behavior.
- Do not require callers to install a no-op manager.

`/hello` with auth enabled:
- Call `authManager.authorize` with `routeClass: helloBootstrap`.
- Authorized: return full hello plus `authManager.helloAuthState(token)`.
- Denied: return HTTP 200 minimal bootstrap including `protocolVersion`, safe app meta keys (`app`, `deviceId`, `deviceName`, `platform`), `serverInfo`, `eventsEndpoint`, `profileRevision`, `authRequired`, `authStatus`, and `authEndpoints`.
- Denied hello must not include `registeredCapabilities`, aggregate state, `capabilities`, or token.

Sensitive routes with auth enabled:
- `GET /state` authorizes before aggregate state; denied returns auth error and exposes no state.
- Capability `GET` resources and `POST` commands authorize before handler invocation; denied must not call handlers.
- Direct dispatch `GET /events` authorizes before introspection fallback.

Auth bootstrap routes:
- Exact `POST /auth/request`, `POST /auth/status`, `POST /auth/claim`.
- System priority over capability routes.
- Do not require Bearer token.
- Call corresponding manager method when auth manager exists.
- `AuthRouteOk` preserves status/body; `AuthRouteDenied` maps to `{ok:false, code, message}`.
- If auth manager is absent, return `401 authorization_required`.

## HttpSseTransport Requirements

Add a nullable `/events` preflight callback, for example:

```dart
void setEventsPreflight(
  Future<RouteResult?> Function(RouteRequest req)? handler,
)
```

For exact `GET /events`:
- Build a `RouteRequest` with method, segments, empty body, headers, and original request.
- Run preflight before setting SSE headers/status, creating subscriber, adding subscriber, writing or flushing `: connected`.
- `null` preflight result proceeds with existing SSE behavior.
- Non-null preflight result writes JSON with its status/body and returns.
- Denied auth produces JSON 401/403, no SSE byte, and no subscriber.
- Authorized/null preflight preserves existing first frame and broadcast behavior.

`ControlPlane.start` must install events preflight when transport is `HttpSseTransport` and auth is enabled.

## Protocol Constraints

- `protocolVersion` remains `1`.
- Auth errors use only existing `{ok:false, code, message}` body shape.
- Token is only read from `Authorization: Bearer <token>`.
- Token must not be accepted from query string, body, path, cookie, SSE data, app meta, or state.

## Acceptance Criteria

1. Auth disabled keeps existing Dart behavior.
2. Dart auth route classification mirrors Kotlin.
3. `RouteRequest.headers` propagates HTTP headers and supports case-insensitive Authorization parsing.
4. Auth-enabled `/hello` without valid token returns HTTP 200 minimal bootstrap and excludes `registeredCapabilities` plus aggregate state.
5. Auth-enabled `/hello` with valid token returns full hello plus auth state.
6. Auth-enabled `/state` without valid token returns 401 and does not expose state.
7. Auth-enabled capability `GET` and `POST` without valid token return 401 and do not invoke handlers.
8. `POST /auth/request`, `/auth/status`, and `/auth/claim` route to the auth manager before capability dispatch.
9. Auth route denied/ok results preserve status code and existing JSON body shape.
10. Auth-enabled HTTP `/events` without valid token returns JSON 401/403 before hijack and never writes `: connected`.
11. Auth-enabled HTTP `/events` with valid token preserves existing SSE first frame and broadcast behavior.
12. `protocolVersion` remains `1`.
