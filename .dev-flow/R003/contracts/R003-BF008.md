### 评估者挑战记录

- **Q1（ci 幂等性与耗时，实质质疑）**：初稿提议 cross-stack 脚本原样重放 tasks.md 四条全量命令，叠加在 ci-check-all 已跑过的 [1]-[5] 之上属双份全量——本地每次增量验证都被拖慢数分钟，且 CI runner 上重复编译提高 flake 面积，幂等性差。→ **采纳修订**（KD-1）：改「存在性断言 + dart/python 定向子集重放」形态，全量责任留在 [1]-[5]，override 只承载定向快验与单独重跑入口。
- **Q2（真机脚本可重入性）**：初稿未定义重复运行行为——残留安装包、evidence 追加混叠会让第二次运行结果不可信。→ **采纳修订**（KD-2.4）：开头 uninstall 容错清理、working 输出覆写、evidence 按 run_at 分节；多设备环境显式报错拒绝盲选。
- **Q3（deferred 边界诚实性）**：评估者要求明确「scripts 就绪 + evidence deferred」模式下 android-page-scope.md 的合法形态——最坏情形是出现推定性三阶段"结果"文本（LLM 产物常见伪造点）。→ **采纳修订**（KD-4）：三阶段未执行时 md 仅为标题+未执行声明的空壳结构；每段原始输出必须带时间戳与产生它的命令，实现者无法也不得编造。deferred log 与 FB002 先例格式一致。
- **Q4（gate log 文件名）**：cross_stack 下划线命名易写成 cross-stack 导致 gate block（gate 按 tasks.md 原文字面量拼 `${TASK_ID}-${layer}-${domain}-test.log`）。→ **采纳**（KD-3）：逐字登记精确文件名并在范围内清单列出。
- **Q5（visual 门归属确认）**：FB002 曾遗留 visual_baseline 由 BF008 采集的预期；但 BF008 domain=backend、tasks.md test_tasks 无 visual 维度、gate L330 仅对 ui domain 强制视觉报告。实读三方一致：本任务无 UI 视觉门，baseline 采集非本合同强制项。→ accepted：范围内不强制 thresholds 固化；如真机窗口打开且实施者顺带采集，作为附加证据记录于 android-page-scope.md，不改变本合同验收边界。
- **Q6（field 一致性）**：negotiation_rounds 与两轮往返对应确认为 2。
