## Implementation Scope

### Goal

在现有 acceptance example app 上落地**页面级 capability demo**：可进入 page A / page B 两个 demo 页面，进入时用 R003-FB001 的 `PageCapabilityScope` 以业务传入 pageId 注册本页 capability，页面内展示 pageId 与本页 active capability 数量；离开页面触发 scoped dispose，且离开后 app capability 与另一页 capability 保持可用。这是 R003 第一个有自有 UI 表面的任务——交付 AcceptanceSpec `acceptance.page_scope.*` 4 个控件本体（BF006 已交付第 5 个 refresh_tools_button）+ 结构层证据；像素级视觉层 deferred 到 BF008。

### 关键决策

- **KD-1 demo 页面结构**：home 页新增 page scope demo 入口区（含 open_button）；两个新页面 `PageScopeDemoPage(pageId: 'page-a', ...)` 与 `PageScopeDemoPage(pageId: 'page-b', ...)`，pageId 常量 `const pageAId = 'page-a'; const pageBId = 'page-b';`（任务定义关键代码片段）。每页用 `BridgeCapability` 构造注册两个 capability：capId 固定 `sample.page.panel` / `sample.page.form`（FB002.2），资源/命令为最小合理占位。页内显示 pageId 文本与 `scope.registeredCount` 数量文本。
- **KD-2 生命周期绑定**：进入页面（push route 后）构造 `PageCapabilityScope(bridge: ..., pageId: ..., pageName?: ...)` 并 await registerAll；close_button / 系统 pop → 先 `await scope.dispose()` 再退出路由。**bridge 来源（Round 1 修订）**：
  - Android：现役 host 是 `AndroidNativePlane`，其 `_bridge` 为私有字段且 `plane.stop()` 会 `dispose` 该 bridge —— demo **不得自建第二个 bridge 实例**（同 channel 二次 `attach()` 抢占 handler 会截走 host 的反向调用）。约定：在 `AndroidNativePlane` 上新增 public getter `NativeControlPlaneBridge get bridge => _bridge;`（example 包内改动，范围内），demo 页从 `AcceptanceController.withHost(AndroidNativePlane(...))` 创建处把该实例向下传给 demo 页面（InheritedWidget 或构造参数均可，实施者定）。
  - 非 Android：`DartPlaneHost` 模式下 app 不持有任何 `NativeControlPlaneBridge`。约定：此平台 demo 页构造专用 `NativeControlPlaneBridge(channel: MethodChannel('...page_scope_demo'))` 通道名与主 channel 不同、不抢占 handler；页面注册在该模式预期失败（native 无对端），走流程图失败分支展示错误文案、count 停留 0，app 不崩——这本身是有价值的降级演示。真机语义正确性由 BF008 在 Android 回收。
  - 验证路径「离开 page A 后 app capability 与 page B capability 保持可用」= A.dispose 只删 `(page, A, id)` key，`(app, id)` 与 `(page, B, id)` 不动（FB001 已保语义，本任务做端到端演示与 widget test 断言）。

### 评估者挑战记录

- **Q1（KD-2，实质缺陷）**：「其它平台用 AcceptanceController 同源 host」不可实现——`DartPlaneHost` 不持有任何 `NativeControlPlaneBridge`；Android 侧 `AndroidNativePlane._bridge` 私有且 `stop()` 会 dispose 它，自建第二 bridge 又会因同 channel 二次 attach 截走 handler。→ **采纳修订**：Android 经新增 public getter 复用 host 同一 bridge 实例；非 Android 用独立通道名的降级桥、注册预期失败走错误分支演示。
- **Q2（KD-3，实质缺陷）**：「refresh_tools_button 由 BF006 已交付」为虚构——grep 全仓该标识仅存在于 AcceptanceSpec yaml 与本契约，BF006/BF007 evidence 无 example 改动。tasks.md 验收标准明确本任务「实现 5 个稳定标识」。→ **采纳修订**：控件本体收归本任务，本地刷新语义、不加协议字段；这也使 page_unregister_on_close 的第二步 tap 可执行。
- **Q3（Hard Gates 对接）**：拟议 evidence 文件名 `R003-FB002-unit-flutter-widget-test.log` / `R003-FB002-regression-test.log` 与 commit gate 计算式 `${TASK_ID}-${layer}-${domain}-test.log` 不符且缺 integration:android deferred log，提交时必被 block（已实读 `scripts/xlfoundry-commit-gate.sh` L284-327）。→ **采纳修订**：更正为 `R003-FB002-unit-flutter-test.log`（主包零回归并入）+ `R003-FB002-integration-android-test.log`（deferred/device_required）。
- **Q4（KD-4 偏离确认）**：主包 `test/` 无法导入 example 包（独立 pubspec，包名 `debug_control_plane_acceptance_example`），偏离论证经实读成立；gate 不校验 tasks.md 文件清单，故无需 allowlist，但偏离必须随 Negotiation Record 留痕。→ **accepted**。
