## Implementation Scope

### Goal

Extend the Python MCP capability mirror so `/hello.registeredCapabilities[]`
scope metadata is preserved in `CapabilitySchema`, diff detection observes app
and page capability changes, and generic meta tool schemas expose optional
selector parameters for the next BF007 forwarding task.

### In Scope

- Modify `python/debug_control_plane/mcp_plane/capability_mirror.py`.
- Modify `python/debug_control_plane/mcp_plane/server.py` only where schema
JSON projection or static tool schemas require it.
- Update `python/tests/test_capability_mirror.py` and, if needed,
`python/tests/test_server.py`.
- Add `CapabilitySchema.scope: str = "app"`,
  `page_id: str | None = None`, `page_name: str | None = None`, and
  `scope_revision: int | None = None`.
- Keep `CapabilitySchema` frozen and tuple-valued so dataclass equality remains
the mirror diff source.
- Parse `/hello.registeredCapabilities[]` top-level
  `scope/pageId/pageName/scopeRevision`.
- Treat missing or malformed `scope` as `app`.
- Treat non-string `pageId/pageName` as `None`.
- Treat `scopeRevision` as an integer only when it is a real integer; bool and
  other malformed values become `None`.
- Ensure malformed metadata is a local schema downgrade, not a device offline
  or auth error, and does not clear the cache as "no capabilities".
- Ensure legacy sentinel schemas from static `target.capabilities` produce
  `scope="app"` and page fields `None`.
- Ensure multiple active page capabilities can coexist, including same
  `capability_id` under different `page_id`; do not deduplicate by bare
  `capability_id`.
- Ensure `refresh(device_id)` returns `True` for schema grow, shrink, page
  unregister, `pageName`, `pageId`, and `scopeRevision` changes; identical
  snapshots return `False`.
- Ensure semantic providers receive the full `CapabilitySchema`; mirror code
  must not hard-code business capabilities or force tool name changes.
- Ensure `list_capabilities` JSON output includes `scope` and, when present,
  `pageId/pageName/scopeRevision`.
- Extend static meta tool input schemas for `invoke_command` and `read_resource`
  with optional `scope`, `page_id`, and `scope_revision`, while preserving
  existing required fields and `additionalProperties: False`.

### Out Of Scope

- Do not implement `BridgeClient.invoke/read` selector header forwarding. BF007
  owns `X-DCP-Capability-Id`, `X-DCP-Capability-Scope`,
  `X-DCP-Page-Id`, and `X-DCP-Scope-Revision` HTTP forwarding.
- Do not implement server handler snapshot stale checks before command/resource
  invocation. BF007 owns stale page call convergence.
- Do not implement App-returned `page_capability_gone` or
  `capability_scope_expired` refresh/list_changed handling. BF007 owns it.
- Do not modify Dart, Kotlin, Flutter, `PROTOCOL.md`, or fixtures.
- Do not generate page identity in Python and do not put `pageId/pageName` into
  capability ids, route paths, MCP tool names, or device ids.
- Do not change `protocolVersion=1`.
- Do not add runtime dependencies or alter Bearer token/auth handling.
