## Implementation Scope

### 目标

在 Kotlin core 的 `Capability` 模型层增加与 Dart/PROTOCOL 对齐的 scope 类型，使旧 capability 默认等价 app scope，page scope 具备明确 `pageId` 参数校验，并为后续 R003-BF005 的 scoped registry/dispatch 提供稳定模型。

### 范围内

- 修改 `kotlin/src/main/kotlin/com/pantas/debug/controlplane/Capability.kt`。
- 新增 `CapabilityScopeType`，取值必须能稳定映射到 wire 字段 `scope` 的 `app` / `page`。
- 新增 `CapabilityScope`，字段语义为：
  - `type: CapabilityScopeType`
  - `pageId: String?`
  - `pageName: String?`
  - `revision: Long?`
- 提供 app 默认 scope。
- 提供 page scope 构造入口，`pageId == null`、空字符串、纯空白必须同步抛出明确参数错误。
- 给 `Capability` 增加兼容式默认 `scope` 属性，使旧匿名实现、`FakeCapability` 和现有测试 double 不需要强制补新成员即可编译，默认值为 app。
- 更新 `kotlin/src/test/kotlin/com/pantas/debug/controlplane/Fakes.kt`，使测试 double 可覆盖 app/page scope，同时保留现有构造调用兼容。
- 新增或更新 Kotlin 单元/golden 测试，覆盖默认 app、page scope、pageId 参数校验，以及 fixture 中 `scope/pageId/pageName/scopeRevision` 字段名和 path array 形状。

### 范围外

- 不修改 Kotlin `ControlPlane` registry 为 scoped key；这是 R003-BF005。
- 不实现 selector header dispatch、`page_capability_gone`、`capability_scope_expired`；这是 R003-BF005 及后续链路。
- 不改变 Kotlin `/state` 或 `/hello` 聚合策略；本任务只铺模型。
- 不新增 `ScopedCapabilityKey` registry、不读取 `X-DCP-*` selector、不新增 scoped unregister 行为。
- 不修改 Flutter bridge、Android plugin registry、Python MCP mirror。
- 不修改 `PROTOCOL.md`、fixtures 或 `protocolVersion=1`。
- 不把 `pageId/pageName` 拼进 capability id、route path 或 tool name。

### 已知约束

- `PROTOCOL.md` 和 `fixtures/` 是跨语言协议真相源。
- 任务清单关键片段中的 `revision` 是内存模型字段；wire/golden 字段必须仍是 `scopeRevision`。
- Golden fixture 只能证明 schema 字段形状，不证明 scoped registry 行为；registry 并存能力由 R003-BF005 验收。
