## Implementation Scope

### 目标
在 `flutter_debug_control_plane/example/lib/src/acceptance_plane.dart` 交付 iOS 模拟器可用的 Dart acceptance harness，提供可启动的 `ControlPlane` + `HttpSseTransport` endpoint、固定 capability、测试 auth manager 和请求日志事实源。

### 范围内
- 新建 `AcceptancePlane`，封装 Dart `ControlPlane.start/stop/register`，`startDartPlane()` 成功后返回可被 Flutter UI 与后续 runner 使用的 endpoint。
- 注册四个固定 capability：`debug.echo`、`debug.deviceInfo`、`debug.secureAction`、`debug.errorCase`，返回稳定 JSON shape，且 `debug.errorCase` 能稳定表达 capability 业务错误。
- 实现测试 auth manager，支持 R001 既有 `/auth/request`、`/auth/status`、`/auth/claim` 流程，不重新定义 wire protocol。
- 实现 Bearer token 校验，覆盖缺失 token、伪造 token、过期 token、拒绝授权等路径；错误语义至少能区分 `denied`、`expired`、`invalid_token`。
- token 仅保存在 App 进程内存或 Flutter 私有状态中；本任务不得把 token 写入 query string、公开日志或持久化明文文件。
- 暴露 request log sink 接口，记录 `timestamp`、`method`、`route`、`capability?`、`authResult`、`statusCode`、`message?`，供后续 UI 任务绑定展示。
- 为 auth manager、fixed capabilities、request log sink 和直接 Dart harness 行为补充 Flutter unit/direct harness tests。

### 范围外
- 不实现 iOS native plugin bridge。
- 不实现 Android native bridge/device 真实链路；Android 真机验收由后续 R002-FF003/R002-BF008 覆盖。
- 不实现 Python acceptance runner 或 shell 脚本；该部分由 R002-BF005 覆盖。
- 不实现授权弹窗 UI、Status/Requests/Controls 页面绑定；该部分由 R002-FF002/R002-FB001 覆盖。
- 不修改 R001 鉴权协议、token 生成算法或跨语言 wire contract。
- 不把设备/模拟器端到端 endpoint 验收强制加入 `ci/ci-check-all.sh`。

### 已知约束
- 架构事实边界在 App debug plane；Python adapter 只能携带凭证和翻译错误，不能作为最终授权判定方。
- HTTP 请求必须使用 `Authorization: Bearer <token>`；不得通过 query string 传 token。
- Dart/Kotlin/Python 的协议字段、错误码和协议版本必须保持一致；R002 只能消费 R001 已有 auth contract。
- `flutter_debug_control_plane/example/` 是真实宿主验收夹具，不得引入产品业务依赖。
- 请求日志是人工验收和脚本诊断的共同事实源，但不得泄露 token 明文。

### 任务流程图
App 启动或测试调用 `AcceptancePlane.startDartPlane()` → 创建 Dart `ControlPlane` 与 `HttpSseTransport` → 注册四个 fixed capability 与测试 auth manager → 返回 endpoint。

未授权请求 → Dart debug plane 进入 auth gate → 创建或复用 pending authorization request → request log sink 记录 `authorization_required`/pending → `/auth/status` 轮询 pending/denied/approved → `/auth/claim` 在 approved 后返回进程内 token 元数据 → Bearer 重试敏感 capability → token 有效则调用 capability 并记录 allowed；缺失/伪造/过期/拒绝则返回对应 auth error 并记录 rejected。

异常：`debug.errorCase` 被调用且 Bearer 有效 → 返回稳定 capability 业务错误 → request log sink 标记 capability error，不能误归类为 auth error。`expireToken()` 或等价测试控制触发后 → 下一次 Bearer 请求返回 `expired` 并要求重新授权。
