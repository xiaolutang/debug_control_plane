### 范围内

  - 语义：不负责启动 app/模拟器（app 由 FF004 集成测试或人工启动，脚本消费 endpoint）；有 endpoint → 转发 `python3 -m pytest python/tests/test_acceptance_flutter_app_auth.py --endpoint=<URL> -v` 并透传退出码；无 endpoint（参数与 env 均缺）→ stdout 打印一行 `setup_required: no endpoint provided (use --endpoint or ACCEPTANCE_ENDPOINT)`，exit code **75**（EX_TEMPFAIL，约定「环境未就绪」专用码，区别于 0=pass / 1-5=测试失败），不算 pass 也不算测试失败。
  - 风格遵循 ci/lib.sh 与现有脚本约定；不修改 ci/ci-check-all.sh，不注册进 CI 聚合（blocked_files 约束，见 Q6）。
- **BF005.2 pytest runner** `python/tests/test_acceptance_flutter_app_auth.py`：
  - endpoint 参数化：pytest 自定义 option `--endpoint`（`conftest.py` 或模块内 `pytest_addoption`），其次 env `ACCEPTANCE_ENDPOINT`；两者皆无 → 每个用例 `pytest.skip("setup_required: no endpoint")"`，汇总输出可见 skip 而非 pass。
  - 连接失败/超时稳定输出：连接被拒/超时（默认单请求 timeout 5s，poll 上限 30s）→ `pytest.skip("setup_required: endpoint unreachable ...")` 或明确 FAIL（区分：所有用例运行前的健康探测（GET / 或 /auth 相关）不可达 → 全部 skip + setup_required；单个用例中途断连 → 该用例 FAIL 并给出稳定消息），不允许裸 traceback flaky。
  - 主链路用例（真实 endpoint 时执行）：`request_authorization(endpoint)`（POST /auth/request {clientLabel, clientNonce} → 202 {requestId, status:pending}）→ 等待 approve（见 Q1 路径 b）→ `claim_token`（POST /auth/claim {requestId} → token + expiresAt）→ 内存保存 token → Bearer retry：敏感路由（debug.secureAction）带 Bearer → 200；不带/无效 token → 401。
  - 无需 approve 的负向用例（协议级，endpoint 可达即可跑）：伪造 token → 401；claim 未 approved 的 requestId → 403/4xx（非 200、无 token 泄漏）；/auth/status 轮询 pending 状态 shape 校验。
  - HTTP 客户端用 Python 标准库 urllib（python/ 包现有零第三方依赖风格保持，见已知约束）。
- **BF005.3 稳定性场景**：无 endpoint（skip/setup_required）、连接失败（连接被拒 → 全 skip + setup_required）、超时（请求超时 → 稳定消息非 flaky traceback）、denied（见 Q3 范围界定）。

### 已知约束
- **wire 事实（已核实 acceptance_plane.dart）**：POST /auth/request → 202 {requestId, status:'pending', clientLabel}；POST /auth/status {requestId} → 状态；POST /auth/claim {requestId} → 未 approved 时返回错误码（authorization_denied/invalid，非 200），approved 后返回 token + expiresAt；敏感路由 Bearer 无效/过期 → 401。capability 路由见 fixed 4 个（debug.echo / debug.deviceInfo / debug.secureAction / debug.errorCase）。
- **无 pending TTL**：plane 侧 pending 请求不过期（无 approval_timeout 服务端语义）；「approval_timeout」只能定义为客户端等待超时（pytest 等 approve 超时 → skip/稳定消息，见 Q3）。
- **无 HTTP deny/expire 路由**：deny 与 expireToken 是 app 内 controller 操作（denyPending/expireToken），协议层不可驱动。
- token TTL 默认 15 分钟：真实过期不可等待，token_expired 场景归 BF008（真机联调驱动 app 内 expire 按钮）。
- python/ 仓库零第三方依赖（标准库 urllib），不引入 requests。
- auth 路由为普通 HTTP POST（非 SSE 流），urllib 直连即可。
- iOS 集成测试（FF004/BF006 harness）与 pytest 的时序协调：BF005 契约采用「endpoint 参数 + 轮询就绪 + approve 由 flutter integration 测试侧驱动」模式（Q1 路径 b）；pytest 不自动点 UI。

### 任务流程图
正常路径：操作者启动 iOS 模拟器 example app（BF006 Dart plane，loopback endpoint）→ `ci/acceptance-flutter-app.sh --target ios-simulator --endpoint http://127.0.0.1:<port>` → pytest --endpoint → 健康探测（GET /）可达 → request_authorization（202 pending）→ flutter integration 测试/操作者驱动 approve（app 内 approvePending）→ pytest 轮询 /auth/status 至 approved → claim_token（token, expiresAt）→ Bearer retry debug.secureAction → 200 → 断言通过（exit 0）。

降级路径 A（无 endpoint）：--endpoint 与 ACCEPTANCE_ENDPOINT 均缺 → 脚本 stdout `setup_required: ...` + exit 75；pytest 单独运行时逐用例 pytest.skip(setup_required)，不误报 pass。
降级路径 B（endpoint 不可达）：健康探测连接被拒/超时 → 全部用例 skip(setup_required: endpoint unreachable) + 稳定单行原因；脚本透传（skip-only 视为 setup_required 输出，exit 75）。
异常路径（运行中断连/单用例超时）：该用例 FAIL + 稳定消息（非 flaky traceback）；等待 approve 超时（30s 上限）→ 该用例 FAIL 并注明「approve 未在 30s 内发生（需 flutter 侧驱动）」。
跨模块交互点：pytest（宿主机）↔ Dart AcceptancePlane HTTP loopback（wire 协议 R001 design 冻结，BF005 只消费）；shell → python3 -m pytest 子进程。
