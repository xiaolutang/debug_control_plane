## Residual Risks

1. BF006 API 缺口（记录，不中断）：`AcceptanceDebugAuthManager.expireToken` 无 token 时静默 no-op 且不产生日志，controller 只能同步置 expired 态而 requestLog 无对应条目；测试需先走 claim 路径才能复现 token_expired。建议后续 renegotiate 补 `expireToken` 返回值或日志事件。
2. `denyPending` 后 pending 请求仍留在 authManager `_pending`（denied 状态），controller 清空了本地 pending 字段；同一 clientNonce 复用请求不会复用 denied pending（BF006 已处理），风险低。
3. `_AcceptanceHomeHost` 在 `didChangeDependencies` 自动 start plane：生产 OK；widget 测试注入 controller 时不自动调用 start（由测试驱动），`const AcceptanceApp()` 路径依赖真实网络可用，沙箱/无网络环境下 endpoint 停留占位（failed 态有日志记录不崩溃）。
4. testWidgets 中真实 plane 操作必须走 `tester.runAsync`（FakeAsync 限制），后续 FF004 integration test 需沿用此模式。
5. 既有 warning：acceptance_plane.dart:496 unused_element_parameter（BF006 遗留，本任务契约豁免不计）。
